# Textile Production Scheduling & Machine Allocation Dataset

## Provenance warning
This is a reproducible **synthetic/simulated dataset**, not real factory data. It is intended for software integration, prototyping, testing, and demonstrating ML pipelines. Do not describe its records or model metrics as evidence of real-world textile-factory accuracy.

Random seed: 20261010.

## Files and approximate scale
- `orders.csv`: 10,000 synthetic orders/batches.
- `machines.csv`: 28 synthetic machines across weaving, knitting, dyeing, printing, and finishing.
- `production_history.csv`: 10,000 synthetic completed operation records with order/batch/machine IDs, planned/actual timestamps, processing duration, setup, queue wait, downtime, idle-after-job estimate, output, quality proxies, rework and deadline outcomes.
- `allocation_candidates.csv`: every order paired with candidate machines for its required process; contains eligibility features and a synthetic selected-machine label generated by a heuristic.
- `machine_availability_calendar.csv`: 28 machines × 180 days × 3 shifts, with synthetic availability and maintenance windows.

## Modeling guidance
1. Duration regression target: `actual_processing_minutes` from `production_history.csv`. Do not use actual end time, actual duration, defects, output, rework, completion, on-time, lateness or other post-outcome fields as predictors.
2. Machine allocation: use `allocation_candidates.csv` grouped by `order_id`; only rank eligible candidates. `historically_selected_machine` is a synthetic heuristic label, not a human-confirmed optimal assignment. Split train/test by order ID or time, not individual candidate rows.
3. Scheduling: calculate feasible start/end times using current queue, calendars, setup/changeover rules, shifts, maintenance and existing assignments. ML predictions must never override hard constraints.
4. Idle time depends on future arrivals and the planning horizon; `idle_after_job_minutes` is simulated and should not be treated as universally predictable ground truth.
5. Compare ML to simple baselines. Report MAE for duration estimates and ranking/selection metrics for allocation.
6. Data rows include `SYNTHETIC_SIMULATION` labels for traceability.

## Limitations
The generator simplifies the factory to one primary operation per order. Real textile production often has multi-stage routing, reservations, shift constraints, operator constraints, changeovers, rework and linked processes. Replace or calibrate these assumptions with genuine production records before claiming operational accuracy.
